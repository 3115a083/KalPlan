# Implementation and security review, updated 2026-10-08

Review against upstream 6ceac42fc1d4ef5ff3d6e706bd07432f90d1a3a9. This is a development build, not a penetration-test certification.

## Implemented
- Native Material 3 list, compact detail, day calendar, direct-manipulation swipe review, history, unclear requests and search. Dispatcher icon 1 is reproduced as a padded adaptive vector. Visual themes, language and light/dark mode are grouped and applied immediately.
- Multiple read-only IMAP accounts/folders, incremental UID/UIDVALIDITY synchronization and bounded batches. Latest 100 messages on first import; subsequent windows catch up. UID reset remaps matching full bounded source snapshots without losing local status.
- AES-GCM Keystore encrypted atomic state, credentials, API keys and OAuth state. Stored schema explicit, plaintext cap 31 MiB, failures do not silently discard history.
- Existing flexible extraction connected to source/evidence, explicit candidate selection and correction with the original message visible. Profiles and fields are created through a guided editor that generates safe internal patterns.
- Visual labels with chip display, subject/body/sender assignment rules and ANY/ALL matching. Compact arrow priority, multi-label interaction rules and configurable duration fallback.
- Global work/travel/km/flat value estimates in integer cents. Each matching label may override only selected price components and inherits the remainder without duplicated settings.
- Selected Android calendars and recurrence/all-day handling, independent title/location/description controls, travel-calendar marking, buffers and both trip legs. Calendar options are requested when enabled and summarized below each calendar. Missing permission/calendar/travel produces unknown or possible feasibility and blocks productive acceptance.
- Explicit manual routing using own API keys/coordinates to Google, HERE, TomTom, openrouteservice or GraphHopper. Atomic daily call budgets, no retries/fallback/geocoding. Coarse offline coordinate estimate labeled approximate.
- Safe two-step reply review, refreshed source and recipient, threading/signature, final calendar check immediately before SMTP DATA, durable send fence and visible unknown-delivery state.
- Tentative reservation after acknowledged SMTP success. Failed calendar write does not resend. Debug simulation and technical test-recipient override; calendar writer blocks debug writes.
- Private notifications and responsive scrollable widget with pending requests and feasibility. Actions open review. Attachment metadata filtering and explicit scoped external viewing.
- Unique WorkManager jobs, backoff, manual/15+ periodic/5-14 best-effort sync and an overnight-capable daily quiet period. Redacted code-only diagnostics, centered five-tap debug footer and manual stable-release lookup.
- Decline replies are disabled by default. A normal decline is a local discard; mail is sent only after the user explicitly enables and confirms that behavior.
- Debug mode generates synthetic feasible, conflicting, unchecked-travel, distant and unclear cases relative to current calendar context. Release defaults contain no domain-specific labels or customer data.

## Findings corrected
| Finding | Correction |
| --- | --- |
| MIME decoded fully before truncation | Bounded decoded streams, 16-depth/200-part limits, unsafe mail enters unclear queue |
| Arbitrary user regex backtracking | RE2/J linear-time engine and profile length/count/group validation |
| Unselected calendar queries | Selected-ID provider filtering; private fields removed before display |
| All-day UTC/local mismatch | UTC date converted to local day boundaries |
| DST time gap or overlap silently normalized | Requires manual review and a valid explicit UTC offset |
| Unsupported TLS 1.3 on older Android | Select supported TLS 1.2/1.3 protocols |
| No durable send fence | Persist before DATA, delivery-unknown blocks retries after ambiguity or process death |
| Unchecked Reply-To/header provenance | Fresh source lookup, strict single address and injection-safe headers |
| Hidden routing origin in UI | Separate internal/visible origin values |
| Post-DATA close failure mislabels delivery | Acknowledged delivery never becomes retryable |
| Debug calendar creation could write | Calendar writer itself rejects debug writes |
| Mutable old action tags | Current verified action commit pins and weekly update checks |

Unit regressions cover MIME caps, ReDoS, HTML active-content removal, recipient/header validation, send fencing, DST, aging, pauses, priority and cents. Record actual successful run evidence in the PR; do not infer completion from workflow configuration.

## Remaining scope and limitations
1. Actual IMAP/SMTP/OAuth providers, calendar writing and routing require account/device testing; no real credentials were supplied.
2. Fixed OAuth redirect cc.stkmn.kalplan:/oauth2redirect must be provider-registered. Microsoft defaults are provided; Google is not a pre-registered one-tap integration.
3. Direct CalDAV, on-device/cloud AI and PGP/MIME are optional future adapters.
4. Bundled postcode/city data and calendar-color editing remain follow-up work.
5. The capped atomic encrypted store needs indexed Room/SQLite migration and retention/export before large-mailbox production use. User-facing labels and profiles no longer require JSON or regular-expression editing.
6. SMTP/calendar cannot be one transaction; reservation failure stays visible. Manual recovery tooling remains follow-up.
7. Stable-release lookup displays a tag, without semantic update comparison or automatic installation.
8. Later mail confirmations/cancellations are not recognized automatically; source mail flags/moves/deletes never change.
9. App-wide distribution license, review of newly changed transitive license obligations and stable release signing remain release preparation.

Live messages above 16 MiB (or with an unavailable size) are rejected before ENVELOPE/BODYSTRUCTURE processing. Oversized source mail stays in the mail account and appears as an unclear placeholder. Provider parser recursion overflow is normalized to an unsafe-MIME result. Traversal limits supplement the trusted protocol library; they do not constitute a complete hostile-server parser sandbox. No attachment bodies are prefetched for normal extraction.
