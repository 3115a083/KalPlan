# Focused review, 2026-10-18

Base: `73e02f712a550c280c73c0f6b25ea10658e15303`, the existing Dispatcher implementation in PR #6. This follow-up uses that development branch; `main` still contains the earlier scaffold.

## Changes

- Calendar queries cover every day touched by the candidate, including the final day and configured context padding. Previously, overnight or multi-day requests queried only their start day and could miss a later conflict.
- An absent origin keeps feasibility at `POSSIBLE`, rather than silently implying no travel. A recent event location or explicit origin can resolve it. Invalid intervals produce a correction reason instead of throwing.
- Planning decisions are separated from Android I/O in `AppointmentAssessment`. The same policy serves cards, details, widgets and the final SMTP recheck. Selected-calendar and hidden-field controls remain enforced.
- Cards refresh after relevant settings, calendar selection, local reservations or sync state changes.
- Guided profile creation saves the same reply-template overrides used by its preview. Empty overrides inherit global templates.
- Status colors follow the chosen app theme even when it differs from the device theme. Labels and custom primary text use relative luminance and a minimum 4.5:1 text contrast on the final opaque background. Readable preferred hues are retained. This component-level check does not establish full accessibility conformance.
- Development version: `0.5.1-dev`, version code 6.

## Regression coverage

Unit cases cover missing/manual/recent-event origins, conflict precedence, the last day of a multi-day request, DST query boundaries, invalid intervals, calendar selection and privacy, failed local reservations, stale routing and text contrast.
