# Profile workbench and local fallback, 0.7.0-dev

The former settings and guided editors now share one workbench. Users select values in normalized local mail, create freely named typed fields, and correct field recognition by changing anchors, selecting a new source or adding a source-compatible alternative. Field names are independent of appointment meanings. One value may supply appointment fields, existing labels, a description and `{feld.key}` reply/calendar template variables.

Literal labeled lines (including empty values), bounded multiline regions, whole sources, table columns and bounded RE2/J patterns are supported. Legacy IDs, matcher order, dependent variables, transforms, direction, locale, date mode and reply templates survive editing. New profiles use schema 2; schema 1 remains readable. A source-dependent field never falls back outside its parent.

Users explicitly save up to ten local examples and expected field values, including negative applicability examples. Correcting an expected value does not secretly change a rule. A re-test reports missing, changed or conflicting results. Examples are mail-containing data, stored with encrypted app state and included in explicit profile export/backups. Drafts use an Activity ViewModel rather than placing large mail bodies in saved-instance bundles. The workbench keeps save/cancel outside its scrolling content.

Preview and mail import use the same extraction pipeline and received-time/time-zone context. Folder assignments take precedence; otherwise specific enabled profile matchers select a unique profile. Competing profiles require review. Manually corrected or acted-on requests cannot be overwritten by local re-extraction. Re-extraction performs no mail/calendar writes and invalidates previous route checks.

When a profile does not find required appointment information, a bounded local fallback ranks date/time context and nearby address fragments. These scores are heuristic confidence, not calibrated statistical probabilities or an ML model. Original evidence and warnings remain visible. Explicitly empty structured values stay empty. Missing or uninterpretable values may produce separate guesses; conflicting evidence requires review. Quotes, visible reply history and signature tails are excluded from fallback. Address fragments are combined only on the same or adjacent lines. Structured date/time context is checked before adding a guessed counterpart from another block. No external AI, geocoding or routing request is involved.

Relative and explicit date mentions are collected together. Equal dates deduplicate; contradictory relative/explicit dates require review. All date spans are masked before time parsing, preventing `19.10` from becoming 19:10. Structured meeting-mode mappings separate a value such as `Ort` from a physical address and from words in its header.

Limits: this remains a review-oriented editor. Repeated table rows or repeated blocks with different values generate conflicting-match warnings; they are not automatically paired into several independently complete appointment records. Fallback handles bounded text and known date/time/address forms and can miss unusual language. Original real-provider mailbox connectivity remains unverified. Test signing differs between CI runs; export user data before switching APKs, without blindly uninstalling an existing installation.

Validation is pending for this implementation. Earlier CI 81 belongs to 0.6.1 and does not validate these changes.
